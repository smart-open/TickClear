## 1. 产品愿景与定位

### 一句话定位

> **点清**是一款以「任务组 + 定时提醒 + 一键清空」为核心、兼顾实用与趣味性的个人任务清理工具，帮助用户管好时间、清空烦恼。

### 产品关键词

| 维度 | 描述 |
|------|------|
| **核心功能** | 每日任务清理、定时提醒（吃药/日程）、一键结束 |
| **差异化** | 任务组批量管理 + 趣味性交互（爽感清空） |
| **情感价值** | 清空任务的成就感 → 清空烦恼的心理暗示 |
| **设计风格** | 简洁、活泼、有呼吸感，不沉闷 |

### 产品定位三角

```

         /    \
        / 点清  \
       /        \
      /__________\
   实用          好玩

## 2. 问题陈述

### 用户痛点

现代人的日常被碎片化任务淹没：

- **遗忘成本高**：忘记吃药影响健康，忘记日程耽误事情
- **任务管理太重**：市面上的 Todo App 要么太复杂（Notion/Jira），要么太简陋（备忘录）
- **缺乏完成感**：传统清单只是打勾，没有「清空烦恼」的心理释放
- **批量任务低效**：早间流程（洗漱/早餐/喂猫）、晚间流程（护肤/阅读/冥想）需要逐条勾选，没有批量管理
- **定时提醒割裂**：吃药提醒在健康 App，日程在日历，任务在 Todo —— 各自为政

### 市场缺口

| 竞品 | 优势 | 缺失 |
|------|------|------|
| TickTick | 功能全面 | 太重，学习成本高 |
| Microsoft To Do | 简洁 | 无任务组，无趣味性 |
| 滴答清单 | 本土化好 | 任务组弱，UI 偏商务 |
| 提醒事项 (iOS) | 原生集成 | Android 不可用，无批量 |
| 喝水/吃药类 App | 定时精准 | 功能单一，无通用任务 |

> **机会**：一款轻量但有深度、实用但有趣的 Android 任务清理工具，填补市场空白。

## 4. 目标与非目标

### 目标（Goals）

| # | 目标 | 衡量标准 |
|---|------|---------|
| G1 | 用户能在 30 秒内完成每日任务清空 | 任务清空时长 P50 < 30s |
| G2 | 定时提醒送达率 > 98% | 系统级闹钟送达统计 |
| G3 | 任务组功能被 60%+ 用户使用 | 创建任务组的用户占比 |
| G4 | 次留 > 50%，7 留 > 25% | 友盟/自定义打点 |
| G5 | 用户感知「清空很爽」 | NPS > 40（v1 内测） |
| G6 | 用户可通过语音 / AI 完成任务的创建、暂停、启用、删除，无需手动逐条操作（语音需先配置云端 ASR 服务商） | 语音/AI 任务管理操作成功率 ≥ 90%；任务组创建率 ≥ 60%，一键清空使用率 ≥ 40% |
| G7 | 语音 / 自然语言创建任务的意图与槽位识别准确（基于用户配置的阿里云 / 腾讯云 ASR） | 抽样评测集意图准确率 ≥ 92%、槽位（时间/重复/名称）填充准确率 ≥ 88% |
| G8 | 语音识别服务商可自由配置（阿里云 / 腾讯云），未配置时语音入口正确禁用并引导配置 | 未配置 → 语音入口禁用率 100%；首次配置引导成功率 ≥ 90%（用户自填第三方 Key 易错、Region 不匹配、额度不足，目标务实化，见【开发就绪度·D17】） |

### 非目标（Non-Goals）

| # | 非目标 | 原因 |
|---|--------|------|
| N1 | 协作/共享任务 | v1 聚焦个人单机使用；协作/分享依赖账号或云端，与「无云端」定位冲突，v1 不做 |
| N2 | AI 被动智能建议（基于行为数据的主动推荐） | v1.1 先做**指令式** AI 任务管理（用户说、AI 执行）；被动推荐依赖大量行为数据，放 v2 |
| N3 | 日历视图 | v1 以「今天」为核心，日历需要更多时间打磨 |
| N4 | 云端账号 / 云同步 / 跨平台云同步 | **纯本地存储**：任务与设置仅存于本机（Room/SQLite + SQLCipher 加密），无账号体系、无云端同步；多设备迁移走本地文件导出/导入 |
| N5 | 端侧离线语音识别 | v1 语音识别采用**用户可配置的云端 ASR**（阿里云智能语音 / 腾讯云语音）：仅临时上传音频用于转写，任务数据始终本地、不依赖云端存储；**端侧全量自然语言离线识别不在 v1 范围**。说明：离线状态下保留**受限离线热词**（预设关键词「暂停 / 启用 / 删除 + 指定任务名」的端侧关键词 spotting，仅做匹配、不做语义理解）作为降级能力，不属于「全量离线 ASR」，与本条不冲突 |

## 7. 功能需求详述

### 7.1 任务组系统（核心差异点）

**任务组**是本产品的核心差异化功能。它支持将多个相关任务打包管理。

#### 数据结构

```
任务组 (TaskGroup)
├── groupId: string
├── groupName: string (如"晨间流程")
├── groupIcon: string (emoji 或图标)
├── groupColor: string (主题色)
├── tasks: Task[] (子任务列表，最少 1 个)
├── isExpanded: boolean (今日视图是否展开)
├── repeatRule: RepeatRule | null (组级重复规则)
├── scheduledTime: Time | null (组级定时)
├── groupStatus: TaskStatus (组级状态：active / paused / completed；组暂停后组内所有任务定时一并挂起)
└── createdAt / updatedAt: timestamp

> **TaskStatus 状态机**：`active`（进行中，定时与提醒生效）→ `paused`（已暂停，定时与提醒挂起，数据保留）→ `completed`（已完成）。`paused` ⇄ `active` 可相互切换（即「暂停 / 启用」），`active`/`paused` → `completed` 为单向。删除为逻辑删除（软删），不进入状态机。
>
> **【审查修订】** 上述 `completed` 终态仅适用于**单任务（非重复）及其 TaskInstance**。重复任务（`repeatRule != null`）的 `Task.status` 停留在 `active`/`paused`，其每次发生对应一个 `TaskInstance`；实例完成后由调度器生成下一次实例，任务本身**不进入 `completed` 终态**，因此「每天 8:00 吃药」才能逐日复现。

单任务 (Task)
├── taskId: string
├── groupId: string | null (所属任务组；null = 独立任务；子任务借此外键关联组，Room 归一化必备)
├── taskName: string
├── status: TaskStatus (任务状态机：active / paused / completed)
├── isCompleted: boolean (兼容旧视图的冗余标记；**实例模型下**：仅单任务(非重复)有意义，= status==='completed'；重复任务的完成态以 TaskInstance 为准，此处恒为 false/弃用)
├── pausedAt: timestamp | null (进入暂停态的时间，用于恢复后判断是否需要补发遗漏提醒)
├── enabledAt: timestamp | null (最近一次启用 / 恢复的时间)
├── scheduledTime: Time | null (任务级定时)
├── repeatRule: RepeatRule | null (任务级重复规则；与组级重复独立，详见下方【审查修订】)
├── locationReminder: LocationReminder | null (位置提醒)
├── notes: string
└── order: number (排序)
```

> **【审查修订 · 数据模型】重复任务与实例模型**。原结构单 `Task` 仅有 `scheduledTime` 而无 `repeatRule`（与 `TaskGroup` 不一致），且状态机的 `completed` 被定义为单向终态，会与「每日重复」类任务冲突——例如「每天 8:00 吃药」完成一次后即终结、次日不再出现、不再提醒，破坏 P0 用例（US-02）。建议引入两层模型：
> - `Task.status` 仅表示任务**是否启用**（`active` / `paused`）；**重复任务永不进入 `completed` 终态**。
> - 每次发生由调度器生成 `TaskInstance`（见下），实例才拥有 `completed`；单任务（非重复）的唯一实例完成后即为终态，可被「一键清空」归档。
>
> 任务实例 (TaskInstance)
> ├── instanceId: string
> ├── taskId: string (关联 Task)
> ├── dueTime: timestamp (本次应完成时间)
> ├── status: TaskStatus (本次实例状态：active / completed；实例无 paused 态)
> └── completedAt: timestamp | null
>
> 完成历史统一由 `TaskInstance` 历史派生为 `CompletionLog`，供 §9 打卡日历 / 连续天数 / 成就与 §10 指标读取；**「一键清空」仅归档当日已完成实例（移出今日列表、写入历史），不物理删除历史**——否则统计将无数据。

**【审查修订】基础类型定义**（原结构仅以类型名引用，未给出字段，补充如下）：

```
RepeatRule
├── type: 'once' | 'daily' | 'weekly' | 'monthly' | 'interval'
├── intervalDays: number | null      (type='interval' 时，每 N 天)
├── intervalHours: number | null     (type='interval' 时，每 N 小时，如每 8 小时吃药)
├── weekdays: number[] | null        (type='weekly'，1-7 表示周一~周日)
├── monthDay: number | null          (type='monthly'，每月第几天)
└── anchorTime: Time                  (当日触发时刻，如 08:00)

Time        // 简化表示：{ hour: int, minute: int }，或 ISO 时间字符串
LocationReminder
├── lat: double
├── lng: double
├── radiusMeters: number              (默认 ≥ 200m)
├── trigger: 'enter' | 'exit'
└── timeWindow: { start: Time, end: Time } | null   (仅在时间窗内触发)
```

#### 任务组行为规则

| 场景 | 行为 |
|------|------|
| 组级定时 | 到时间整个组弹出提醒，展开后可逐条完成 |
| 组内单任务定时 | 组内某个任务单独设置时间（如组"晚间流程"中「21:00 吃钙片」） |
| 组内一键完成 | 展开组 → 点击「全部完成」→ 组内所有任务**当日实例**标记完成（重复任务次日重新出现，非永久删除） |
| 部分完成 | 组内只完成了 2/5，组显示「2/5」进度条 |
| 组重复规则 | 组可设置「每天重复」，组内所有任务**按日历日生成当日实例**（重置锚点 = 当日 0 点，非按完成时间顺延）；「每 N 小时 / 每 N 天」类间隔以**上次完成时间**为锚点，跨午夜照常顺延 |

> **【开发就绪度·数据模型裁决】**（支撑实现，避免开发返工）
> 1. **`Time` 类型定死**：统一为 `{ hour: Int (0–23), minute: Int (0–59) }` 的结构体，**禁止混用 ISO 时间字符串**，避免 Room 存储与跨端解析的时区歧义；所有重复/定时锚点均基于**设备本地时区**。
> 2. **组级 / 任务级重复冲突裁决**：当 `Task.groupId != null` 且其所属 `TaskGroup.repeatRule != null` 时，**子任务的 `repeatRule` 被忽略，频率以组级为准**（组内 UI 不暴露单任务重复设置）；仅当 `Task.groupId == null`（独立任务）时，任务级 `repeatRule` 才生效。组级 `scheduledTime` 驱动整组提醒；组内单任务可设独立 `scheduledTime`（如「21:00 吃钙片」），但重复频率继承组级。
> 3. **`CompletionLog` 实体（统计与打卡的唯一数据源）**：
> ```
> CompletionLog
> ├── logId: string
> ├── taskId: string                (关联 Task)
> ├── instanceId: string | null    (对应 TaskInstance；单任务非重复的唯一实例完成时亦写入)
> ├── completedAt: timestamp        (实际完成时间，本地时区)
> ├── dateLocal: string            (YYYY-MM-DD，本地日期；用于热力图/连续天数，防止时区跨日错位)
> └── source: 'manual' | 'voice'   (完成动作来源；「一键清空」仅为归档，不改变此值)
> ```
> 4. **外键与级联**：`Task.groupId` → `TaskGroup.groupId` 设 `@ForeignKey(onDelete = CASCADE)`；删除组时其所有子任务实例一并级联软删（置 `deletedAt`），避免孤儿数据。`TaskInstance` 须对 `(taskId, dueTime)` 建唯一索引，防止调度器重复生成。

- [ ] 任务组最少包含 1 个子任务，无上限（建议 ≤ 20）

### 7.2 定时提醒系统

#### 提醒类型

| 类型 | 描述 | 示例 |
|------|------|------|
| **单次定时** | 指定日期时间，提醒一次 | 「明天 15:00 开会」 |
| **每日重复** | 每天固定时间提醒 | 「每天 8:00 吃药」 |
| **每周重复** | 指定星期几提醒 | 「每周一三五 19:00 健身」 |
| **每月重复** | 指定每月第几天提醒 | 「每月 1 号交房租」 |
| **自定义间隔** | 每 N 天/N 小时 | 「每 8 小时吃一次药」 |
| **位置提醒** | 进入/离开指定范围 | 「到 XX 药店附近提醒买药」 |

> **【实现状态·自定义间隔】**：v1.0 已落地「每 N 天 / 每 N 小时」。`TaskEntity` 新增 `repeatIntervalHours`（`repeatIntervalDays` 保留）；`ScheduleUtils.dueMinutesForDate` 将「每 N 小时」拆为当日多个生效分钟（如每 8 小时从锚点起拆成 08:00/16:00…），`TaskInstanceRepository` 据此生成多个实例，`ReminderScheduler` 为每个实例排独立精确闹钟（`PendingIntent` 以 `instanceId` 哈希为 requestCode，避免同任务多实例互相覆盖）。编辑页重复下拉新增「自定义间隔」并提供「天/小时」单位切换。

#### 提醒通道策略

```
提醒级别：
├── 高优先级（吃药类）
│   └── 系统闹钟 API (AlarmManager + FullScreenIntent)
│       → 全屏弹窗，类似来电，确保用户看到
│
├── 中优先级（日程类）
│   └── 高优先级通知 + 声音 + 震动
│       → 通知栏常驻，需手动消除
│
└── 低优先级（普通任务）
    └── 标准通知
        → 静音时段自动降级为静默通知
```

> **【深度审查·定时技术要点】**
> - **精确闹钟权限**：Android 12+ 精确闹钟需 `SCHEDULE_EXACT_ALARM`（或 13+ 的 `USE_EXACT_ALARM`），targetSdk 34 下未声明 `setExact()` 将抛异常；Android 14 起全屏意图（`FullScreenIntent`）受系统抑制，需引导用户在设置中授予「额外提醒权限」。
> - **AlarmManager 才是精确路径**：定点/每日/每周提醒必须用 `AlarmManager`(exact) + `BroadcastReceiver`，WorkManager 默认**不保证精确时间**，仅适合模糊周期同步；二者分工须明确，否则「8:00 吃药」会漂移。
> - **重启重排**：设备重启后 AlarmManager 闹钟清空，须监听 `BOOT_COMPLETED` 重新排程全部启用的定时，否则重启即丢提醒（直接影响送达率）。
> **【开发就绪度·位置提醒技术方案（决策已定）】**：原 `Geofencing API` 依赖 Google 移动服务（GMS），国内大量无 GMS 设备（部分华为/荣耀新机）位置提醒将直接失效。**已决策改为**：① 定位基于系统 `FusedLocationProvider` / `LocationManager`，**不依赖 GMS**；② 围栏触发采用**厂商推送围栏**（华为 Push Kit 地理围栏、小米 / OPPO / vivo 等厂商推送围栏）或前台地理围栏服务；③ 或明确**限定仅支持含 GMS 的机型 / 发行地区**。radius ≥ 200m；具体厂商围栏接入清单在 v1.1 开发期确认。
> - **「跳过」语义（吃药类）**：对重复任务，「跳过」= 跳过**本次实例**、保留任务并于下一周期再提醒，不等于删除任务。

#### 验收标准

- [ ] 定时提醒送达率 ≥ 98%（含后台被杀场景）
- [ ] 支持从通知栏直接标记「完成」
- [ ] 支持「稍后提醒」（5分钟/15分钟/30分钟）

#### 时间冲突醒目提示（新增，决策要求）

> **【开发就绪度·时间冲突（决策）】**：当多个任务的提醒时间重叠 / 撞车时，须在**创建编辑时**与**今日视图展示时**给出醒目提示，避免用户漏看或重复被打扰。

**1. 冲突检测范围（无需新字段，由 `scheduledTime` / `repeatRule` 派生实例时间计算重叠）**
- 保存任务（创建 / 编辑）时：检测与已有任务在「同一时间点」或「重叠时间窗」是否存在 ≥ 2 个提醒。
- 今日视图实时检测：当日同一时刻存在 ≥ 2 个提醒，或高优先级（吃药类）提醒与其他提醒重叠。

**2. 冲突定义（可评估阈值）**
- 强冲突：两任务 `scheduledTime`（含重复派生实例）完全相同，或同一高优先级提醒重叠。
- 弱冲突：时间窗相邻（如 5 分钟内）多个普通提醒。

**3. 醒目 UI 提示**
- **创建 / 编辑页**：检测到冲突时，页面顶部显示**红色警示条**「⚠ 与「{任务名}」时间冲突（{时间}）」，并列出冲突项；用户可读但仍允许保存（知情决策）。
- **今日视图**：冲突时间点用**橙色 / 红色标记 + 角标**（如「2 项冲突」），点击展开查看重叠任务。
- **提醒触发时**：若同刻多提醒，通知按优先级堆叠，高优先级置顶。

**4. 验收标准**
- [ ] 创建 / 编辑保存时若与已有任务时间冲突，显示醒目红色警示条且列出冲突项

执行（建任务 / 暂停 / 启用 / 删除）
   ↓
结果反馈（Toast + 轻动画 + 语音播报可选）
```

#### 7.5.4 任务状态机与「暂停 / 启用」语义

在 7.1 已引入 `TaskStatus`（`active` / `paused` / `completed`）。本节能能力补充其业务语义：

| 操作 | 前状态 | 后状态 | 系统行为 |
|------|--------|--------|---------|
| 暂停（pause） | active | paused | 挂起该任务（组）的全部定时与提醒；今日视图将其移入「已暂停」分组；不删除历史完成记录 |
| 启用 / 恢复（resume） | paused | active | 恢复定时与提醒；暂停期间应触发但未触发的提醒默认**跳过**，避免恢复瞬间轰炸 |
> **【开发就绪度·D11 跳过边界（决策）】**：显式举例——「每周一健身」任务在周三暂停、周六恢复：恢复后**仅跳过周三那次已过的发生**，下周一按 schedule 正常提醒；不会补发周三提醒，也不会丢失后续周期。多次跨发生点的暂停同理：每次恢复只跳过「已过的本次发生」，其余周期照常。
| 完成 | active / paused | completed | 标记完成，计入统计 |
| 删除（delete） | 任意（非 completed） | 逻辑删除 | 软删，进入回收站保留 30 天，可恢复；**到期后由每日定时清理任务（WorkManager 周期 / 每日扫描 `deletedAt`）自动硬删，不可恢复**（见【开发就绪度·回收站】） |

**暂停 vs 删除**：暂停用于「暂时不需要但将来还要用」（出差、休假、临时搁置）；删除用于「永远不再需要」。两者均可语音触发，但**删除在语音场景需二次确认**，防止口误误删。

> **【审查修订】回收站（缺失补全）**：§7.5.4 / §7.5.11 要求「软删 + 回收站保留 30 天可恢复」，但全文未描述回收站入口与恢复交互。补充：① 入口——「设置 → 本地数据管理 → 回收站」；② 列表展示软删任务/任务组及删除时间；③ 支持单条/批量「恢复」（恢复原状态）与「彻底删除」（立即硬删）；④ **超过 30 天由每日定时任务自动硬删，不可恢复**（可配置保留天数，默认 30）；⑤ 「清除本地数据」操作应提示是否一并清空回收站。
>
> **【开发就绪度·D10 概念区分（决策）】**：在 UI 文案与帮助中明确两类「从列表消失」的差异——**一键清空 = 已结案归档**：已完成实例移入 `CompletionLog` 历史，**不可恢复、仅留统计**；**回收站 = 误删可恢复**：任务未真正删除，30 天内可找回，到期才清除。两者入口与提示文案须区分，避免用户混淆「清空的去哪了 / 能否找回」。

#### 7.5.6 解析确认卡（Parsing Confirmation Card）

为防止语音误识别造成「误建 / 误删」，所有写操作执行前必须展示确认卡：

```
┌─────────────────────────────────┐
│  🤖 我识别到你要：              │
│  ┌───────────────────────────┐  │
│  │ 创建任务                    │  │
│  │ 名称：开会                  │  │
│  │ 时间：明天 15:00（单次）    │  │
│  │ 重复：无                    │  │
│  └───────────────────────────┘  │
│  [✎ 修改]   [✕ 取消]   [✓ 确定] │
└─────────────────────────────────┘
```

- **创建类**：默认展示确认卡，可快速「确定」或「修改」（修改进入精简编辑态，预填解析值）。
- **暂停 / 启用类**：轻量确认（顶部 Snackbar 带「撤销」），降低打断感。
- **删除类**：**强确认**（弹窗 + 明确后果文案），语音场景须显式说「确认删除」或点确定，避免口误。

> **【开发就绪度·解析结果契约】**（NLU 输出与确认卡/执行层之间的数据契约，避免前后端/模块扯皮）
> ```
> ParsedIntent {
>   intent: 'create' | 'pause' | 'resume' | 'delete' | 'query'
>   confidence: Float              // 0~1，低于阈值(建议 0.6)强制确认卡
>   targets: [                    // 可能为多个（歧义场景供用户二选一）
>     { kind: 'task' | 'group', id: String | null, name: String, matchScore: Float }
>   ]
>   slots: {
>     name?: String
>     time?: { type: 'absolute' | 'relative' | 'daily' | 'weekly' | 'interval',
>              value: Any, tz: 'device' }
>     repeat?: RepeatRule
>     location?: LocationReminder
>     group?: String               // 目标组名（创建到某组时）
>   }
>   needClarify: Boolean           // true 时前端展示追问而非确认卡
>   clarifyPrompt?: String
> }
> ```
> NLU 仅输出上述结构，执行层据 `intent` + `targets` + `slots` 落库；`confidence` 与 `needClarify` 决定走「确认卡 / Snackbar / 强确认 / 追问」哪条路径（见 §7.5.7）。

> **【开发就绪度·D20 信任模式（决策）】**：为减少熟练用户摩擦，设置中提供「信任模式 / 免确认」开关。**开启后**：创建 / 暂停 / 启用等常规操作默认直接执行（仍展示轻量 Snackbar「撤销」）；**删除等危险操作无论是否开启信任模式均强制强确认**（防误删 / 口误）。默认关闭。

> **【实现状态·D20】**：v1.0 已落地。设置页新增「信任模式」开关（默认关闭）；`AssistantViewModel.handleTool` 在信任模式下对非危险工具（建任务等）直接 `mcpTools.commit` 落库并以系统消息反馈，删除 / 暂停 / 更新 / 恢复 / 移除等危险工具无论是否信任均强制弹出确认卡（二次确认），符合「防误删」硬约束。

#### 7.5.7 歧义澄清与错误处理

| 场景 | 处理 |
|------|------|
| 同名多任务（如两个「吃药」） | 追问：「你是指『吃维生素』还是『吃钙片』？」语音二选一 |
| 未识别到意图 | 「没太听懂，要建任务、暂停、启用还是删除？」 |
| 槽位缺失（只说「提醒我吃药」无时间） | 追问时间：「几点提醒？」或给默认（当天 09:00）并标注「未指定时间」 |
| ASR 置信度低 | 在确认卡高亮疑似识别词，提示用户核对 |
| 离线 / 网络失败 | 降级：仅支持离线热词（如「暂停所有」「删除 XXX」），复杂语义提示联网后重试 |
| 危险批量操作（暂停 / 删除全部） | 强制确认卡 + 明确影响范围 |

#### 7.5.8 隐私与安全

- **数据永不上云（任务数据）**：任务、设置、统计等用户数据仅存于本机（Room/SQLite + SQLCipher 加密），无账号、无云端同步，不调用任何云端存储服务。
- **运行期联网边界（【深度审查】）**：所谓「纯本地·无云端」指**任务数据永不上云**；但启用语音后，App 会在用户说话时向阿里云/腾讯云 ASR 发起网络请求完成转写，属于**功能运行所需的临时联网**，并非数据同步。须在隐私章节与应用内声明中明确区分二者，避免用户误以为 App 完全离线。
- **NLU 解析边界（【审查修订】）**：意图/槽位解析默认在**端侧**完成。若启用可选云端 NLU 增强（见 Q7），仅上传**脱敏后的指令文本**用于语义理解，**不上传任何任务内容**；该增强默认关闭，用户需显式开启并知情。
- **语音识别是可选云端增强**：语音识别使用**用户自行配置的**阿里云 / 腾讯云 ASR。仅在用户主动说话时**临时上传音频用于转写**，传输全程 TLS 加密；**不上传任何任务内容**，音频不在本机持久化、服务端按服务商策略处理（不用于训练 / 留存由用户与服务商协议约定）。
- **未配置则本地优先**：未配置任何语音服务商时，App 完全离线可用，仅语音入口不可用，其余功能（手动 / 任务组）不受影响。
- **权限**：麦克风权限首次使用语音时申请，可随时在系统设置撤回；撤回或未授权时，语音入口禁用并提示「请先在设置中配置语音识别服务商」。
- **误唤防护**：仅有显式入口或耳机键唤起才收音，无「常驻后台监听」（不做「嘿 点清」式常驻唤醒）。

#### 7.5.9 语音识别服务商配置（核心新增）

语音识别**不是开箱即用**，必须由用户自行配置云端 ASR 服务商与密钥后才可用；未配置时语音功能整体不可用。

**配置入口**：设置 → 语音识别配置。

**支持服务商**

| 服务商 | 所需凭据 | 说明 |
|--------|----------|------|
| 阿里云智能语音（智能语音交互 NLS） | AppKey + AccessKey ID / AccessKey Secret（或令牌） | 一句话识别 / 实时语音流；方言与中文识别成熟 |
| 腾讯云语音（ASR） | SecretId + SecretKey | 一句话识别 / 实时语音识别；支持方言与热词 |

> 凭据以加密方式存储于本机 `EncryptedSharedPreferences`（基于 Android Keystore，而非直接将 Secret 存入 SQLCipher 明文表），不随任务数据导出；切换 / 清除服务商时一并清除本地凭据。
>
> **【深度审查·测试上传】**：§7.5.11「测试并保存」会发起一次极短音频上传以校验凭据有效性，同样属于上传音频行为，须在隐私说明与测试弹窗中明示用户。

> **【实现状态·§7.5.9】**：v1.0 已落地且能力扩展。配置页支持 4 类服务商：系统识别（Xiaozhi 服务端 / 本地 `SpeechRecognizer` 兜底）、OpenAI 兼容（Whisper 类一键转写）、腾讯云 ASR（本地 TC3-HMAC-SHA256 签名）、阿里云 NLS（本地 RPC HMAC-SHA1 签名）；各家凭据存于 `EncryptedSharedPreferences`（Keystore），不上云。配置页提供「测试」按钮（`AsrProvider.test()` 发起一次极短识别校验凭据），通过后才提示保存；`AssistantViewModel` 语音门控已强化为「已配置且凭据齐备」才展示可用麦克风（§7.5.9 门控表）。

**配置流程**

```
设置 → 语音识别配置
  ├─ 选择服务商：○ 阿里云智能语音  ○ 腾讯云语音
  ├─ 填写 API Key（密码框，默认隐藏）
  ├─ 填写 Secret Key（密码框，默认隐藏）
  ├─ [ 测试并保存 ]  →  调用一次极短识别验证凭据有效性
  └─ 状态：● 已启用（阿里云）  /  ○ 未配置（语音功能不可用）
```

**功能门控（Gating）**

| 状态 | 语音入口（🤖 / 语音面板） | 行为 |
|------|--------------------------|------|
| 已配置且凭据有效 | 可用（高亮） | 正常收音、转写、解析 |
| 未配置 | 禁用（置灰） | 点击提示「请先在设置中配置语音识别服务商」并跳转配置页 |
| 凭据失效 / 测试失败 | 禁用并标红 | 提示「密钥无效，请重新配置」 |
| 麦克风权限未授予 | 禁用 | 引导系统授权 |

**降级与兜底**

- 识别失败 / 网络异常：语音面板内提供「改用文字输入」入口，切到文字模式仍可下达相同指令（创建 / 暂停 / 启用 / 删除）。
- 同一指令集（见 7.5.5）同时服务于语音与文字两种输入，保证「未配置语音也能用文字管任务」。
- **【审查修订】成本提示**：语音识别使用**用户自带的**阿里云/腾讯云凭据，ASR 调用产生的费用（按调用量/时长计费）由用户在其服务商账户承担，与点清无关。建议在「语音识别配置」页与首次启用时明确提示此点，避免用户误以为免费。

#### 7.5.10 与现有功能的关系

- **任务组**：暂停 / 启用 / 删除 均支持任务组级操作（级联到子任务），与 7.1 组行为规则一致。
- **双粒度并存**：语音 / 文字 / 手动操作均可作用于**「任务组」或「单个任务」**两种粒度——说「暂停晨间流程」作用于整组，说「暂停吃维生素」只作用于该子任务；时间线视图中组标题提供组级操作入口，展开后的单个任务提供单任务操作入口，互不冲突。
- **定时系统**：暂停即挂起 AlarmManager / WorkManager 定时；启用恢复调度。
- **今日视图（时间线）**：今日预览按时间线组织；已暂停任务（组）从时间线主序列移出，归入独立「已暂停」可折叠分组，启用后回到原时间锚点。
- **一键清空**：仅作用于 `completed` 任务；暂停态任务不参与清空。
- **趣味性**：语音建任务成功播放专属「叮 + 星愿」音效；暂停播放「咔嗒」挂起音；启用播放「叮」恢复音。

#### 7.5.11 验收标准

- [ ] 语音建任务意图识别准确率 ≥ 92%（评测集），槽位准确率 ≥ 88%
- [ ] 支持设置 / 暂停 / 启用 / 删除 四类指令，且均经确认卡或 Snackbar 二次确认
- [ ] 任务组级暂停 / 启用 / 删除 正确级联到子任务
- [ ] 单个任务级暂停 / 启用 / 删除 仅作用于该任务，不影响同组其他任务
- [ ] 今日预览按时间线（计划时间）组织，无定时任务归入「随时」区
- [ ] 暂停后定时不再触发；启用后恢复触发且不轰炸历史遗漏提醒（默认跳过）
- [ ] 删除为软删，进入回收站保留 30 天并可恢复
- [ ] 离线状态下热词指令（暂停 / 启用 / 删除指定任务）可用
- [ ] 麦克风权限未授予时，语音入口禁用并引导授权
- [ ] 方言（粤语 / 川渝 / 闽南等）识别在 v1.1 至少覆盖 2 种，准确率 ≥ 85%
- [ ] 端到端语音建单任务平均耗时 < 4s（含 ASR + 确认）
- [ ] 误删率（用户执行后 10s 内撤销的比例） < 5%

## 11. 技术架构建议

### 技术选型（推荐）

| 层次 | 技术方案 | 理由 |
|------|---------|------|
| **语言** | Kotlin | Android 官方推荐，协程友好 |
| **UI 框架** | Jetpack Compose + Material3 Adaptive | 声明式 UI，动画能力强，原生支持 WindowSizeClass 响应式布局 |
| **响应式布局** | WindowSizeClass + Compose Adaptive | 手机/平板/分屏自动切换布局 |
| **架构** | MVVM + Repository | 清晰分层，可测试 |
| **本地存储** | Room (SQLite) | 结构化数据，支持复杂查询 |
| **定时任务** | WorkManager + AlarmManager | 兼容各版本，后台可靠性高 |
| **位置提醒** | 系统定位（FusedLocationProvider/LocationManager）+ 厂商推送围栏（华为/小米/OPPO/vivo）或限定 GMS 机型 | 不依赖 GMS，国内设备可用 |
| **动画** | Lottie + Compose Animation | Lottie 做复杂动画，Compose 做微交互 |
| **依赖注入** | Hilt | Google 官方推荐 |
| **数据备份** | DataStore + 手动导出 JSON | v1 本地备份 |

> **【审查修订】平台基线**：全文未声明 `minSdkVersion` / `targetSdkVersion`。考虑到 `WindowSizeClass`、Geofencing、FullScreenIntent 等行为随 API 级别变化，建议补充：**minSdk 24（Android 7.0）** / **targetSdk 34+**（适配 Android 14 通知权限与全屏意图限制）。

### 关键技术挑战

| 挑战 | 方案 |
|------|------|
| **后台提醒可靠性**（国产 ROM 杀进程） | 引导用户开启「自启动」+「电池优化白名单」；提供设置向导 |
| **位置提醒（无 GMS）** | 系统定位 + 厂商推送围栏（或限定含 GMS 机型），半径 ≥ 200m；弱网/无围栏时降级为周期性位置轮询 |
| **动画性能** | Lottie 预加载，降级方案：低端机用简化动画；平板双栏动画确保 60fps |
| **平板布局切换** | WindowSizeClass 动态断点，分屏/折叠屏展开收起不丢状态 |
| **数据安全** | 本地 Room 加密 (SQLCipher)；除用户主动配置的语音识别服务（仅临时上传音频）外，不联网、不上传用户任务数据 |

## 14. 平板适配设计

### 14.1 适配策略总览

点清从 v1.0 起即支持 Android 平板，采用 **自适应布局（Adaptive Layout）** 策略，非简单的拉伸放大。

| 适配原则 | 说明 |
|----------|------|
| **内容优先** | 利用大屏空间展示更多内容，而非单纯放大 |
| **单手友好** | 核心操作区域保持在拇指热区范围内 |
| **分屏支持** | 支持 Android 分屏/多窗口模式 |
| **横竖兼容** | 横屏和竖屏均提供优化布局 |
| **统一数据** | 手机和平板共享同一数据源，切换无感 |

### 14.2 断点系统

采用 Jetpack Compose 的 `WindowSizeClass` 作为断点依据：

| 窗口宽度 | 分类 | 对应设备 | 布局策略 |
|----------|------|---------|---------|
| < 600dp | Compact | 手机竖屏 | 单栏布局（默认） |
| 600dp ~ 840dp | Medium | 手机横屏 / 小平板竖屏 | 单栏 + 侧边抽屉 |
| ≥ 840dp | Expanded | 平板横屏 / 大平板 | **双栏布局**（核心体验） |

> **设计原则**：所有布局断点基于 **当前窗口宽度** 而非设备物理尺寸，天然支持分屏和多窗口。

### 14.3 布局方案

## 附录 D：开发约束与接口契约（支撑实现）

> 本附录由「开发就绪度审查（第三轮）」补充，目的是让开发拿到文档即可动手，减少"需求没写清→返工→扯皮"。所有条目均以 **【开发就绪度】** 标注，**不改动前文产品逻辑**，仅收敛工程契约。其中标注「需设计回填」的色值/字号/Lottie 等，应在 UI 定稿后由设计稿回填具体数值，PRD 阶段先定结构与口径。

### D.1 权限清单

**AndroidManifest 声明**

| 权限 | 用途 | 级别 | 备注 |
|------|------|------|------|
| `RECORD_AUDIO` | 语音收音 | 运行时（危险） | 首次进语音面板申请 |
| `SCHEDULE_EXACT_ALARM` | 精确闹钟（高优先级提醒） | 运行时（Android 12+） | 不声明 `setExact()` 直接抛 `SecurityException` |
| `POST_NOTIFICATIONS` | 发送通知 | 运行时（Android 13+） | 未授权则提醒降级为 toast |
| `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION` | 位置提醒围栏 | 运行时（危险） | 仅位置提醒功能需申请 |
| `RECEIVE_BOOT_COMPLETED` | 重启后重排闹钟 | 普通 | 见 §7.2 重启重排 |
| `USE_FULL_SCREEN_INTENT` | 全屏来电式提醒（Android 14 受抑制） | 普通 | 高优先级吃药类；需引导用户额外授权 |
| `INTERNET` | 语音 ASR 临时联网 | 普通 | 仅启用语音后使用 |

**运行时权限请求时机**：进入语音面板 → 申请 `RECORD_AUDIO`；创建高优先级提醒 → 引导 `SCHEDULE_EXACT_ALARM`（跳转系统设置页，非对话框）；首次启动 → 引导 `POST_NOTIFICATIONS`；创建位置提醒 → 申请定位权限。任一被拒，对应功能置灰并说明原因，不阻断其余功能。

### D.2 通知渠道（NotificationChannel，Android 8+ 必须预创建）

| 渠道 ID | 名称 | Importance | 声音/震动 | 关联提醒级别 |
|---------|------|-----------|-----------|--------------|
| `ch_alarm_high` | 重要提醒（吃药等） | HIGH + `FullScreenIntent` | 默认铃声 + 震动 | 高优先级 |
| `ch_reminder_mid` | 日程提醒 | DEFAULT | 铃声 + 震动，通知栏常驻 | 中优先级 |
| `ch_reminder_low` | 普通任务 | LOW | 无（静音时段自动归入此渠道并静默） | 低优先级 |
| `ch_silent` | 静默（22:00–07:00 降级） | MIN（`IMPORTANCE_MIN`，比 LOW 更静默、无通知栏提示，符合静默预期） | 无 | 静音时段低优 |

> 渠道 ID 一经发布**不可改名/改 Importance**（覆盖安装保留用户设置），故 ID 与语义需评审锁定。

### D.3 ASR 接口契约骨架（v1.1 最大开发风险，务必先行）

> 这是 v1.1 落地的最大不确定点：文档此前未定义任何接口形状。建议先抽象 `AsrClient` 接口，阿里云 NLS / 腾讯云 ASR 各自实现，**业务层只依赖接口**，便于替换、Mock 与单测。

```
interface AsrClient {
    suspend fun recognize(audio: AudioStream, params: AsrParams): AsrResult
}
data class AsrParams(val language: String = "zh-CN", val enableHotword: Boolean)
sealed interface AsrResult {
    data class Success(val text: String, val confidence: Float) : AsrResult
    data class Failure(val code: AsrErrorCode, val message: String) : AsrResult
}
enum class AsrErrorCode { QUOTA_EXHAUSTED, AUTH_FAILED, NETWORK, AUDIO_FORMAT, TIMEOUT, UNKNOWN }
```

- **协议选择**：一句话/短指令用**一句话识别**（REST/WebSocket 短音频）；连续长语音用**实时流式**（WebSocket）。v1.1 先用一句话识别即可覆盖全部指令。
- **音频规格**：建议 `16kHz / 16bit / 单声道 PCM`（阿里云 NLS、腾讯云均支持，避免转码损耗）。
- **鉴权（决策：本地签名，无后端代理）**：用户下载 App 后，在「设置 → 语音识别配置」填入**自己的** AppKey / AccessKey Secret；App **本地**用该密钥按服务商规范**直接签名生成临时 Token**（阿里云 NLS、腾讯云 ASR 均支持本地 AccessKey 签名获取 Token，无需任何后端代理），Token 缓存并按过期时间刷新。**Secret 仅留在本机 `EncryptedSharedPreferences`，绝不离开设备、不上传、不打进请求体**。「测试并保存」通过即代表该用户自有密钥可用。详见【开发就绪度·决策】。
- **超时与重试**：单次识别超时 **8s**，失败自动重试 1 次（网络类），仍失败走「改用文字输入」降级（见 §7.5.9）。
- **错误码映射**见 D.4。

### D.4 统一错误码与 UX 映射（全局规范，避免各处零散处理）

### D.5 数据导出 / 导入 JSON Schema（版本化，否则迁移即丢数据）

```json
{

  "appVersion": "1.1.0",
  "data": {
    "taskGroups": [ { "groupId": "...", "groupName": "...", "repeatRule": null, "...": "..." } ],
    "tasks": [ { "taskId": "...", "groupId": "...|null", "status": "active", "repeatRule": {...}, "...": "..." } ],

- **导入兼容策略**：`schemaVersion` 低于当前 → 执行增量迁移后导入；高于当前（备份来自更新版本）→ **拒绝导入并提示**，禁止静默丢字段。
- **敏感数据**：`EncryptedSharedPreferences` 中的 ASR 凭据**不入导出文件**；导入后需用户重新配置语音。

### D.6 Room Schema 版本与迁移策略

- **当前 `DATABASE_VERSION = 1`**（首版）。新增 `TaskInstance`、`CompletionLog`、为 `Task` 增加 `groupId` 外键时，**必须 +1 并编写 `Migration`**，禁止依赖 `fallbackToDestructiveMigration`（会清空用户数据）。
- **Entities**：`TaskGroup`、`Task`、`TaskInstance`、`CompletionLog`、`Setting`（键值表）。
- **索引**：`Task.groupId`、`TaskInstance(taskId, dueTime)` 唯一、`CompletionLog.dateLocal` 普通索引。
- **迁移测试**：每次 migration 必须写 Room 注入测试（旧 schema 建库 → migrate → 断言新结构可读写），纳入 D.10 的 CI 门禁。

### D.8 指标采集口径与上报策略（不接第三方埋点；§10 指标本地可算）

| 事件名 | 触发时机 | 关键参数 |
|--------|----------|----------|
| `task_created` | 创建任务/组成功 | `type`(single/group), `has_time`, `has_repeat`, `source`(manual/voice) |
| `task_completed` | 标记完成 | `task_id`, `source`, `is_instance`(重复实例) |
| `task_paused` / `task_resumed` | 暂停/启用 | `scope`(task/group) |
| `group_created` | 建组 | `subtask_count` |
| `reminder_fired` | 提醒触发 | `level`(high/mid/low), `delivered`(是否成功) |
| `clear_today` | 一键清空 | `cleared_count`, `streak_days` |
| `voice_session` | 语音会话 | `asr_result`(success/fail), `intent`, `error_code` |
| `theme_changed` | 切换主题 | `theme` |
| `app_open` / `app_background` | 前后台 | — |

- **上报 SDK（决策：不引入第三方埋点）**：**本 App 不接入任何第三方埋点 / 分析 SDK**（如 Firebase Analytics）。指标获取方式：① 连续打卡天数、完成率等**完全本地计算**（见 D.9），无需上报；② 留存 / 活跃等大盘指标依托**应用商店后台**（Google Play Console / 国内商店开发者平台）或系统级数据，不自行采集用户行为；③ 如需自定义事件观测，仅做**本地轻量日志 / 可选匿名导出**，不出端。此举同时简化隐私合规（无需第三方数据共享声明）。详见【开发就绪度·决策】。
- **合规**：本 App 不采集 / 上报任何行为埋点，故无第三方数据共享风险；语音音频绝不入库（仅临时上传 ASR 转写，见 §7.5.8）；如提供本地日志导出，仅含结构字段、不含任务文本；国内上架随包提供隐私政策链接。
- **崩溃率**口径：崩溃上报（如需，可选轻量方案，仍非分析 SDK）目标 `crash-free users` ≥ 99.5%，对应 §10 崩溃率 < 0.5%；无埋点不影响该指标（可由商店后台 / 自研极简上报获取）。

### D.9 指标计算口径（避免"完成率"各算各的）

- **连续打卡天数（streak）**：以 `CompletionLog.dateLocal` 为基准，本地时区。**当日只要存在 ≥1 条完成记录即算"打卡"**；若 `dateLocal = 今天` 且当前时间已过设定的"断签判定点"（建议本地 23:59）仍无完成记录，则 streak 清零并从次日记重。跨时区旅行以设备本地日期为准（不追溯 UTC）。**【开发就绪度·不允许补卡（决策）】**：**App 不提供任何补卡 / 补登入口**；streak 一旦因某自然日无完成记录而断签，即从 0 重计，不可事后补救。**【开发就绪度·D16 记录 / 展示时机（决策）】**：连续打卡天数 **v1.0 起即本地记录**（写入 `CompletionLog.dateLocal`），但**统计页 / 打卡日历热力图在 v1.1 才展示**（见 §12 路线图），避免范围误读。
- **完成率** = 已完成实例数 / 应完成实例数（基于 `TaskInstance` 生成量），**非按任务数**（否则重复任务会稀释分母）。今日完成率 = 今日 `completed` 实例 / 今日生成实例。
- **DAU/MAU**：以 `app_open` 去重设备/账号（本 App 无账号，按设备匿名 ID）按自然日/月统计。
- **人均日完成任务**：`SUM(task_completed)` / `DAU`。

### D.11 多窗口 / 并发 / 数据观察者约定

- **单一事实源**：所有列表/统计均经 `Repository → Room Flow → ViewModel StateFlow`，UI 只读 StateFlow；禁止在 Composable 内直接读 DB。
- **DB 单例**：`Room.databaseBuilder(...).addCallback(...)` 进程内单例（`@Singleton`）；**通知 `BroadcastReceiver` 与 App 同进程**，避免多进程 DB 锁竞争。
- **写操作**：统一经 `Dispatchers.IO`；拖拽排序的批量 `order` 更新必须包在 `@Transaction` 内，防止中间态被观察者渲染出跳变。
- **多窗口**：平板分屏/折叠屏共用同一 DB 与同一组 Flow，任一窗口的写会即时反映到另一窗口（无需跨进程同步）。
- **重启重排**：`BOOT_COMPLETED` Receiver 读取所有 `status=active` 且 `repeatRule/scheduledTime` 非空的 Task，重新 `AlarmManager.setExact()`（见 §7.2）。
