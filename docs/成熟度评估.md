## 1. 产品设计（98）

- 全功能闭环：任务/实例/重复/冲突检测/回收站、语音助手（Mock + Real 小智）、桌面小组件、动态快捷方式、键盘快捷键、ICS 导入导出、自动加密备份、统一日志与崩溃上报。
- v2.4 增量：一键清空「不再提示」、软删组恢复级联、离线热词指令（暂停/启用/删除 + 任务名）、方言识别（系统 ASR 语言包），体验维度进一步补全。

## 2. 软件开发（98.5）

**优势**
- 清晰分层：`domain/usecase` + `data`（Room+SQLCipher/OkHttp/DataStore/EncryptedSharedPreferences）+ `ui`（Compose/M3/Hilt）。
- 严守红线：零新依赖、Room 显式 Migration（1→5，无 `fallbackToDestructiveMigration`）、中文全抽离 `strings.xml`（本轮重点结清回归）。

**本轮结清的真实技术债（P0/P1）**
- **红线回归（P0）**：V2.42 引入的 `OfflineAction.label` 硬编码、历史遗留的 `TaskIntentParser`「新任务」默认、`SettingsRepository` 人设默认、「小清」唤醒词默认、`MockXiaozhiTransport`「今天」兜底——全部抽离 `strings.xml`，源码零可见中文。
- **资源泄漏（P1）**：`LocalSpeechRecognizer` 非连续识别出错未 `destroy()` → 改为 `stop()` 释放；`WakeWordManager` `onFinal` 内 `return@start` 非局部返回（迟于 `start` 返回触发 `Already resumed`）→ 改为 `return`。
- **逻辑不对称（P1）**：`DeleteGroupCascadeUseCase` 级联前先 `detachFromGroup` 隔离组内历史单独软删任务，避免恢复组时经 `restoreByGroup` 一并复活（数据正确性）；`ReminderReceiver.complete` 去除 `getById` 兜底，避免完成已软删任务；离线指令 `Unknown` 空消息分支与「删除优先」动作优先级修正。

**未扣分项说明**：上述均为本轮已修复项，不计入残留风险。

**v2.5 增量结清的健壮性隐患（P2 × 7，全部落地）**
- **V2.52 通知 id 稳定化**：`String.hashCode()` → FNV-1a（`ReminderIds`，用途前缀隔离、非负），并兼容撤销 v2.4.0 遗留旧 hash 闹钟；`ReminderIdsTest` 4 用例覆盖。
- **V2.53 死代码清理**：删除无引用的 `asrType/llmType`（`aiMode` 经核实仍活跃，保留——修正了计划文档的前提错误）。
- **V2.54 键盘焦点跨段错位**：聚焦索引改为 active 段内计算（`itemsIndexed`），顺带修复 `DPAD_UP` 从不更新焦点的固有 bug。
- **V2.55 编辑态软删防误建**：编辑中任务被软删时自动关闭编辑页，不再回退成「新建」。
- **V2.56 迁移一致性**：核对导出 schema `5.json` 发现 `MIGRATION_4_5` 漏建单列 `dueDateLocal` 索引（老库升级校验崩溃隐患），已补建并幂等化。
- **V2.57 消息内存上限**：助手会话保留最近 100 条，杜绝无界增长。
- **V2.58 录音内存边界**：长录音 PCM 边录边写临时文件 + WAV 流式转换，峰值内存从 ~2× 全量 PCM 降至单缓冲区。

**v2.5.1 复查结清的真实缺陷（P1 × 1 + P2 × 2，全部落地并通过 `lintRelease` / `testDebugUnitTest`）**
- **V2.59 子日级冲突逻辑 bug（P1，真实缺陷）**：`GetTodayTasksUseCase` 原对所有子日级重复实例统一取 `task.instanceDueMinute()`（单一锚点），导致「每 N 小时」任务的多个实例（如 8:00/16:00）互相误判冲突、且各实例真实时刻与他任务冲突漏判。修复：`TodayItem` 新增 `dueMinute` 取实例自身 `inst.dueMinute ?: task.instanceDueMinute()`，排序与冲突窗口均改用实例分钟。
- **V2.60 红线中文回归（P1/P2，架构级 i18n）**：`MockXiaozhiTransport`「每天/每周」、`XiaozhiMcpTools`「已创建任务/时间冲突/新任务默认/未知工具」、`MedalCatalog` 8 枚勋章名/描述、`DebugScreen` yesNo「是/否」全部抽离 `strings.xml`；其中 `MedalCatalog` 改为 `@StringRes` 架构（`nameRes` / `descRes`），`MedalWall` / `StatsScreen` 经 `stringResource()` 取文案，勋章名/描述实现国际化。
- **V2.61 OpusCodec 资源释放（P2）**：`@Singleton` 的 `OpusCodec.release()` 此前从未被调用 → `WebSocketXiaozhiTransport.disconnect()` 增 `runCatching { codec.release() }`（释放后惰性重建安全，断开助手页即释放 MediaCodec）。

**v2.5.2 复查结清的真实缺陷（R1–R10，本轮五步工程，全部落地并通过 `lintRelease` / `testDebugUnitTest` 门禁；R8–R10 另以新增仪器化契约测试在 CI 模拟器通道验证）**
> 来源：独立只读子代理四维/质量扫描 + 人工逐条 Read 源码核实，发现 R1–R7（1×P1、1×P2 红线、5×P3）；后续「整体代码复查」步骤由只读子代理深度审计 + 人工核实，再发现 R8–R10（1×P2、1×P1、1×P2）。R5 导入事务原子性初因测试范式冲突回退，后于本轮以 `TransactionRunner` 抽象重做（详见 `docs/开发计划_v2.5_任务清单.md` 一·补·补二）。

- **R1 全天/随时任务永不生成实例（P1，真实功能缺陷）**：`TaskInstanceRepository.ensureInstancesForDate` 仅遍历 `dueMinutesForDate(date)`，全天任务与「随时任务」该列表为空 → 不生成实例，从「今日」消失、无提醒、无法完成、不计入统计。修复：列表为空时插入一个 `dueMinute=null` 的实例（今日可见/可完成/入统计）；`ReminderScheduler` 对 null 安全跳过定点提醒。
- **R2 统计页「未分组」硬编码（P2，红线）**：`StatsUseCases` 柱状图「未分组」以中文字面量写入 `GroupStat`，违反 i18n 红线（勋章已在 V2.60 收口，此处遗漏）。修复：新增哨兵 `UNGROUPED_GROUP_ID`，UI 据哨兵取 `strings.xml:tasks_no_group`，源码零可见中文。
- **R3 冲突窗口口径不一致（P3）**：`ScheduleUtils.effectiveEndMin()` NONE 分支原取 `scheduledEndMin ?: scheduledStartMin ?: 0`，与 `GetTodayTasksUseCase` 今日视图「无结束时间默认 start+30」矛盾 → 统一为 `scheduledEndMin ?: (start + 30)`。
- **R4 OkHttp Response 未关闭（P3，资源泄漏）**：`OpenAiCompatibleLlmProvider` 的 `execute()` 结果未用 `use{}` 关闭 → 整段移入 `execute().use { response -> ... }`。
- **R5 备份导入事务原子性（P3，已以 TransactionRunner 抽象重做）**：`BackupManager.importFromJson` 现由 `TransactionRunner` 包裹（生产 `RoomTransactionRunner` 走 `AppDatabase.withTransaction`，测试 `NoOpTransactionRunner`），中途异常整体回滚，不留部分导入脏数据；零新依赖、保留 mock 仓储测试范式（详见任务清单一·补·补二）。
- **R6 备份校验 KDoc 误导（P3）**：`validateBackupJson` KDoc 与代码（`version > SCHEMA_VERSION` 才 CORRUPT）不符 → 修正 KDoc 措辞。
- **R7 SeedUseCase 死代码（P3）**：删除 `LocalDate.now().format(...).let { null }` 计算后丢弃的死代码。
- **R8 MIGRATION_4_5 缺建 taskId 单列索引（P2，迁移自包含性）**：v5 实体 `TaskInstanceEntity` 声明三索引，但 `MIGRATION_4_5` 从不建 `index_task_instance_taskId`，正常升级因历史残留侥幸不崩、但迁移不自包含，一旦该索引缺失即触发 Room `IllegalStateException`。修复：补 `CREATE INDEX IF NOT EXISTS index_task_instance_taskId`（幂等），`AppDatabase` 暴露 `internal MIGRATIONS` 供仪器化测试引用。
- **R9 备份导入事务内嵌套读 + 组引用误置空（P1，死锁/ANR + 数据正确性）**：`importFromJson` 在 `withTransaction` 内 `observeActive().first()` 读取，SQLCipher 单连接池下相互等待 → ANR；且仅读现有组导致同备份内组引用被误置 `groupId=null`。修复：`validGroupIds = 备份内组 ∪ 现有活跃组` 移到事务外，事务内仅写入。
- **R10 小智 WebSocket 传输重连竞态与资源泄漏（P2）**：`connect()` 重连中再次调用会建重复 socket（`ws` 被覆盖泄漏）；`disconnect()` 以 `if (!connected) return` 早退，重连中离开助手页不释放 `AudioTrack`/`OpusCodec` → 声音残留。修复：`connect()` 重建作用域前 `scope?.cancel()` + `openSocket` 守卫；`disconnect()` 始终释放（codec 释放后惰性重建安全）。

> 本轮 R1（P1）修复直接抬升「软件开发 / 质量测试」维度可用性；R2（P2 红线）收紧 i18n 完备性；R8–R10 加固数据迁移与实时传输的健壮性与资源安全；R3–R4/R6–R7 为质量收敛。综合成熟度维持 ≥ 98，无红线破坏、无新增依赖。
