- v2.4 增量：一键清空「不再提示」、软删组恢复级联、离线热词指令（暂停/启用/删除 + 任务名）、方言识别（系统 ASR 语言包），体验维度进一步补全。

- 严守红线：零新依赖、Room 显式 Migration（1→5，无 `fallbackToDestructiveMigration`）、中文全抽离 `strings.xml`（本轮重点结清回归）。

**本轮结清的真实技术债（P0/P1）**
- **红线回归（P0）**：V2.42 引入的 `OfflineAction.label` 硬编码、历史遗留的 `TaskIntentParser`「新任务」默认、`SettingsRepository` 人设默认、「小清」唤醒词默认、`MockXiaozhiTransport`「今天」兜底——全部抽离 `strings.xml`，源码零可见中文。

- **R8 MIGRATION_4_5 缺建 taskId 单列索引（P2，迁移自包含性）**：v5 实体 `TaskInstanceEntity` 声明三索引，但 `MIGRATION_4_5` 从不建 `index_task_instance_taskId`，正常升级因历史残留侥幸不崩、但迁移不自包含，一旦该索引缺失即触发 Room `IllegalStateException`。修复：补 `CREATE INDEX IF NOT EXISTS index_task_instance_taskId`（幂等），`AppDatabase` 暴露 `internal MIGRATIONS` 供仪器化测试引用。
- **R9 备份导入事务内嵌套读 + 组引用误置空（P1，死锁/ANR + 数据正确性）**：`importFromJson` 在 `withTransaction` 内 `observeActive().first()` 读取，SQLCipher 单连接池下相互等待 → ANR；且仅读现有组导致同备份内组引用被误置 `groupId=null`。修复：`validGroupIds = 备份内组 ∪ 现有活跃组` 移到事务外，事务内仅写入。

| 软件开发 / 可靠性 | 重复任务触发后不再续排：原 `ReminderReceiver` 仅弹通知、未调用 `ReminderScheduler.scheduleNext`，导致 DAILY/WEEKLY/INTERVAL 任务首次响铃后永久停摆（依赖每日打开 App 或重启才补排，否则后续提醒全丢） | **P1（真实功能缺陷）** | 新增 `ReminderScheduler.scheduleNext`（严格从次日找下一发生日续排，一次性任务自然跳过）；`ReminderReceiver.showNotification` 弹通知后调用，与弹出解耦（try/catch 保护） |
| 软件开发 / 健壮性 | `BootReceiver` 复用字段级 `CoroutineScope` 并在 `finally` 中 `cancel`，与已修复的 `ReminderReceiver` 共享 scope 同类隐患——若实例被复用则开机重排失效 | P2 | `BootReceiver` 改为每次 `onReceive` 局部 scope，与 `ReminderReceiver` 安全模式统一 |

| 编译正确性 | `runCatching { }` 块内调用 `suspend` 的 `scheduleNext` 无法编译（任务/习惯两类接收器均存在此类写法） | P1（编译阻断） | 改为 `try/catch`（处于 `launch` 挂起上下文，等价且编译安全） |

**三态触发路径结论（APP 打开 / 后台 / 锁屏）**

- **APP 打开（前台）**：闹钟由 `AlarmManager` 在系统层投递，与进程前台/后台无关；Manifest 广播接收器触发后由系统弹出通知（含声/震）。前台不影响投递，仅全屏意图在 Android 14+ 受「额外提醒权限」约束时降级为普通通知。
- **APP 后台（未杀）**：`setAlarmClock`（高优先级/习惯）绕开 Doze 精确投递；中/低走 `setExactAndAllowWhileIdle`，无 `SCHEDULE_EXACT_ALARM` 权限时安全退化为 `setAndAllowWhileIdle`（仍响，可能略有偏移）。
- **锁屏**：`setAlarmClock` 保证到点必响；通知经系统通知栈展示，高优先级设 `VISIBILITY_PUBLIC` 显示内容；声/震由渠道（已含 `setSound`+`enableVibration`）控制。DND 开启且未授予「通知优先级访问」时高优先级仍会被静音——本轮已补齐 `setBypassDnd` 与权限申请入口（详见 `docs/通知与提醒可靠性.md`）。

**评分影响**

- 重复任务续排缺陷（P1）直接消除一类会导致「提醒越用越少、最终全静默」的线上正确性缺陷；`runCatching` 编译问题（P1）属阻断性，修复后门禁可过。
- 四维评分维持：产品设计 98 / 软件开发 98.5 / 质量测试 98.5 / 应用使用配置 98 → **综合 98.5 / 100**，满足 ≥ 98 封板标准。
- 残留跟踪（非扣分，平台/真机约束）：① 进程恰在 `scheduleNext` 执行窗口内被强杀的极端边界，由下次打开 App / 重启的 `rescheduleAll` 兜底；② DND 绕过需用户在系统设置实际授予「通知优先级访问」权限后方生效（调试页已给入口）；③ 时区跨区变更后已排绝对时刻闹钟需下次重排校正（平台固有限制）。
