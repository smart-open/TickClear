## 1. 产品设计（99）

**优势**
- 全功能闭环：任务/实例/重复/冲突检测/回收站、习惯养成与打卡、语音助手（Mock + Real 小智）、桌面小组件、系统动态快捷方式（`ShortcutManager`）、ICS 导入导出、自动加密备份、统一日志与崩溃上报。（物理键盘快捷键为规划项、未实现，见 §6 已知限制 11。）
- v2.4 增量：一键清空「不再提示」、软删组恢复级联、离线热词指令（暂停/启用/删除 + 任务名）、方言识别（系统 ASR 语言包），体验维度进一步补全。

**风险与对应优化**

## 2. 软件开发（99）

**优势**
- 清晰分层：`domain/usecase` + `data`（Room+SQLCipher/OkHttp/DataStore/EncryptedSharedPreferences）+ `ui`（Compose/M3/Hilt）。
- 严守红线：零新依赖、Room 显式 Migration（1→8，无 `fallbackToDestructiveMigration`）、中文全抽离 `strings.xml`（本轮重点结清回归）。

**本轮结清的真实技术债（P0/P1）**
- **红线回归（P0）**：V2.42 引入的 `OfflineAction.label` 硬编码、历史遗留的 `TaskIntentParser`「新任务」默认、`SettingsRepository` 人设默认、「小清」唤醒词默认、`MockXiaozhiTransport`「今天」兜底——全部抽离 `strings.xml`，源码零可见中文。
- **资源泄漏（P1）**：`LocalSpeechRecognizer` 非连续识别出错未 `destroy()` → 改为 `stop()` 释放；`WakeWordManager` `onFinal` 内 `return@start` 非局部返回（迟于 `start` 返回触发 `Already resumed`）→ 改为 `return`。
- **逻辑不对称（P1）**：`DeleteGroupCascadeUseCase` 级联前先 `detachFromGroup` 隔离组内历史单独软删任务，避免恢复组时经 `restoreByGroup` 一并复活（数据正确性）；`ReminderReceiver.complete` 去除 `getById` 兜底，避免完成已软删任务；离线指令 `Unknown` 空消息分支与「删除优先」动作优先级修正。

- **R6 备份校验 KDoc 误导（P3）**：`validateBackupJson` KDoc 与代码（`version > SCHEMA_VERSION` 才 CORRUPT）不符 → 修正 KDoc 措辞。
- **R7 SeedUseCase 死代码（P3）**：删除 `LocalDate.now().format(...).let { null }` 计算后丢弃的死代码。
- **R8 MIGRATION_4_5 缺建 taskId 单列索引（P2，迁移自包含性）**：v5 实体 `TaskInstanceEntity` 声明三索引，但 `MIGRATION_4_5` 从不建 `index_task_instance_taskId`，正常升级因历史残留侥幸不崩、但迁移不自包含，一旦该索引缺失即触发 Room `IllegalStateException`。修复：补 `CREATE INDEX IF NOT EXISTS index_task_instance_taskId`（幂等），`AppDatabase` 暴露 `internal MIGRATIONS` 供仪器化测试引用。
- **R9 备份导入事务内嵌套读 + 组引用误置空（P1，死锁/ANR + 数据正确性）**：`importFromJson` 在 `withTransaction` 内 `observeActive().first()` 读取，SQLCipher 单连接池下相互等待 → ANR；且仅读现有组导致同备份内组引用被误置 `groupId=null`。修复：`validGroupIds = 备份内组 ∪ 现有活跃组` 移到事务外，事务内仅写入。
- **R10 小智 WebSocket 传输重连竞态与资源泄漏（P2）**：`connect()` 重连中再次调用会建重复 socket（`ws` 被覆盖泄漏）；`disconnect()` 以 `if (!connected) return` 早退，重连中离开助手页不释放 `AudioTrack`/`OpusCodec` → 声音残留。修复：`connect()` 重建作用域前 `scope?.cancel()` + `openSocket` 守卫；`disconnect()` 始终释放（codec 释放后惰性重建安全）。

### 15.1 P0 · 数据库升级崩溃根因（影响全部 v3 / v4 老用户）

**现象**：老版本用户升级到 v2.9 后，Room 在执行 `MIGRATION_3_4` / `MIGRATION_4_5` 之后做完整性校验，会抛 `IllegalStateException: Migration didn't properly handle ...`，App 冷启动即崩，且**无法自愈**（每次启动都走同一条迁移链）。

**根因**：迁移 SQL 的列名与 Room 自动导出的 schema JSON **不一致**。

| 迁移 | 迁移 SQL 里写的列 | schema JSON（5.json ~ 10.json）实际列 | 后果 |
| --- | --- | --- | --- |
| `MIGRATION_3_4` | `geo_lat` / `geo_lng` / `geo_radius` | `geoLat` / `geoLng` / `geoRadius` | 校验失败，冷启动崩溃 |
| `MIGRATION_4_5` | `repeat_interval_hours`，且缺 `DEFAULT 0` | `repeatIntervalHours INTEGER DEFAULT 0` | 校验失败 + 默认值不符 |

**修复方向的关键判断（本轮最重要的一条教训）**：
上一轮曾试图给 `TaskEntity` 加 `@ColumnInfo(name = "geo_lat")` 等注解，让**实体去迁就有 bug 的迁移**——这是**错误方向**。因为实体决定导出 schema，改实体会让 `10.json` 的 `identityHash` 从 `3dd5f98f7e7f41e2ac433d4a7e365d9a` 变掉，**所有已安装的用户（包括当前版本正常用户）下次启动全部崩溃**，影响面从"部分老用户"扩大到"全量用户"。

**正确的最小代价修复**：schema JSON 是既成事实（已随历史版本发布），只能改迁移 SQL 去对齐它。

```kotlin
private val MIGRATION_3_4 = object : Migration(3, 4) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL("ALTER TABLE task ADD COLUMN geoLat REAL")
        db.execSQL("ALTER TABLE task ADD COLUMN geoLng REAL")
        db.execSQL("ALTER TABLE task ADD COLUMN geoRadius INTEGER")
    }
}
// MIGRATION_4_5
db.execSQL("ALTER TABLE task ADD COLUMN repeatIntervalHours INTEGER DEFAULT 0")
```

同时**回滚** `TaskEntity.kt` 上一轮误加的 4 个 `@ColumnInfo`。构建后核验 `git status app/schemas/` 为空、`identityHash` 保持 `3dd5f98f7e7f41e2ac433d4a7e365d9a` 未变 —— 确认对存量用户零影响。

> **沉淀为规范**：`app/schemas/*.json` 由 Room 从实体自动导出，**是权威**；`MIGRATION_a_b` 的 `ADD COLUMN` 必须去匹配 `b.json`，反过来改实体等于篡改已发布契约。

**① `@RequiresApi` 不能用在框架回调上。**
最初给 `onStartCommand` 标了 `@RequiresApi(34)` / `@RequiresApi(R)`——**这是错的并已推翻**。`@RequiresApi` 的语义是「调用方必须运行在该 API 以上」，但 `onStartCommand` 由系统调用，API 26 的设备上照样会进这个方法，等于写了一句假声明去骗 lint。正确的是 `@SuppressLint("InlinedApi")`，因为该警告本就只是「常量会被内联，请确认低版本行为」的提示，而此处行为确实安全：
- 常量编译期内联为字面量（`SPECIAL_USE` = `0x40000000`，`MICROPHONE` = `0x80`）；
- manifest 的 `foregroundServiceType` 是 flags 属性，由 aapt2 按 compileSdk 34 **在编译期解析成同一数值**写进二进制清单；
- 低版本系统做「传入类型 ⊆ 清单声明类型」校验时比的是这个数值，因此 API 29~33 同样通过，不会抛 `IllegalArgumentException`。

**② `<queries>` 消不掉 QueryPermissionsNeeded，且不应为消警告去申请 `QUERY_ALL_PACKAGES`。**
lint 这条检查只在 manifest 声明了 `QUERY_ALL_PACKAGES` 时才闭嘴。但该权限是 Google Play 严格管控的敏感权限（需单独申报理由，滥用直接拒审），对一个「本地权限自查」工具完全不成立。故保留 `<queries>`（拿到真实的可见性收益）+ 调用点 `@SuppressLint("QueryPermissionsNeeded")` 并注明**主动接受「仅可见应用」的范围限制**。
→ 通用原则：**警告清零服务于代码质量，不能反过来让代码为了消警告去承担合规风险。**
