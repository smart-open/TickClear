## 一、代码质量与健壮性（当前可开发，零新依赖优先）

- [ ] **V2.52 · 通知 id 稳定化（防 hashCode 碰撞覆盖）**
  - `ReminderReceiver` 用 `instanceId.hashCode()` 作通知 id，理论上哈希碰撞会互相覆盖通知/全屏意图。
  - 方案：采用更分散的确定性哈希（如 FNV-1a 对 `instanceId` 字节）替代默认 `String.hashCode()`，并对动作后缀（`z`/`k`）保持隔离；长期可引入稳定 int 映射表。
  - 验收：单测覆盖同一 `instanceId` 不同动作得到不同 id；碰撞概率显著下降。

- [ ] **V2.53 · 清理遗留死代码 `aiMode/asrType/llmType`**
  - `SettingsRepository` 仍保留 Phase 5 旧键 `aiMode/asrType/llmType`（及其 setter），已被 `assistantMode/llmProvider/asrProvider` 取代。
  - 方案：确认无 UI/测试引用后移除接口与实现，或标 `@Deprecated`（保留迁移兼容）。
  - 验收：`grep` 无残留引用；`lintRelease` 0 warning。

- [ ] **V2.54 · TodayScreen 键盘焦点跨 active/done 段错位**
  - `focusedIndex` 基于 `state.items`（active+done 合并）序号，但 LazyColumn 把列表拆成 active/done 两段；done 段存在时高亮与「空格/回车完成」目标错位。
  - 方案：聚焦索引仅在 active 段内计算（基于 instanceId 而非合并序号）。
  - 验收：键盘 `↑↓` 高亮与 `空格/回车` 操作目标一致（单测或人工）。

- [ ] **V2.55 · TodayScreen 编辑态软删后误建任务防护**
  - 任务被软删后 `editingTask` 变 `null` → `TaskEditSheet` 以 `initial=null` 打开成「新建」，可能误建重复任务。
  - 方案：编辑态缓存 Task 快照，软删后关闭编辑而非回退到新建。
  - 验收：软删正在编辑的任务不再弹出新建表单。

- [ ] **V2.56 · AppDatabase 空迁移与导出 schema 一致性核验**
  - 空迁移 1→2、2→3 须与 `app/schemas` 下导出 v1/v2/v3 schema 一致；若存在历史结构变更会导致老库（v1/v2）升级 Room 校验失败崩溃。
  - 方案：核对 `app/schemas` 是否存在且字段与 ALTER 一致；不一致则补 Migration 或校正 schema。
  - 验收：全新安装 + 从 v1/v2 升级路径在模拟器均可正常打开。

- [ ] **V2.57 · AssistantViewModel 消息无上限内存控制**
  - `messages` 随长会话无限增长。方案：截断/分页保留最近 N 条（如 100）。
  - 验收：超长会话内存不再单调增长（单测或人工）。

- [ ] **V2.58 · AudioCapture 长录音 PCM 内存边录边写**
  - `startAccumulate` 整段 PCM 累积在内存，超长录音有 OOM 风险。
  - 方案：边录边写临时文件，停止时再编码，降低峰值内存。
  - 验收：长录音（>5min）不发生 OOM。
