## 一·补·补二 · v2.5.2 复查修复（2026-07-25，本轮五步工程新发现）

> 来源：用户本轮「五步工程」第二步——独立只读子代理四维/质量扫描 + 人工逐条 Read 源码核实，发现并**当轮修复** R1–R7；后续「整体代码复查」步骤再审，由只读子代理深度审计 + 人工逐条核实源码，又发现并修复 R8–R10。全部零新依赖，均通过 `./gradlew :app:testDebugUnitTest :app:lintRelease` 门禁（R8–R10 另以新增仪器化契约测试在 CI 模拟器通道验证）。
> **R5（导入事务原子性）** 初因与「mock 仓储纯 JVM 单测」范式冲突而回退，后于本轮以 `TransactionRunner` 抽象重做（生产走 `AppDatabase.withTransaction`，测试用 `NoOpTransactionRunner`），既补齐原子性又保留既有测试范式。

- [x] **R1 · 全天 / 随时任务永不生成实例（P1，真实功能缺陷）** ✅
  - 问题：`TaskInstanceRepository.ensureInstancesForDate` 仅遍历 `task.dueMinutesForDate(date)`；全天任务（`allDay=true`）与「随时任务」（`scheduledDate=null`）该列表为空 → 不生成任何实例。后果：此类任务从「今日」消失、无提醒、无法完成、不计入统计。
  - 修复：列表为空时插入恰好一个 `dueMinute=null` 的实例（`"${taskId}@$date"`），使其在今日可见、可完成、可纳入统计；`ReminderScheduler` 对 `dueMinute=null` 已安全跳过（不排定点提醒），无崩溃。

- [x] **R2 · 统计页「未分组」硬编码（P2，红线 i18n）** ✅
  - 问题：`StatsUseCases` 柱状图「未分组」分组名以中文字面量写入 `GroupStat`，违反「中文全抽离 `strings.xml`」红线（勋章 i18n 已在 V2.60 收口，此处遗漏）。
  - 修复：新增哨兵 `UNGROUPED_GROUP_ID = "__ungrouped__"`，柱状图改用哨兵 id；`StatsScreen` 据哨兵取 `strings.xml:tasks_no_group`（已有 "未分组"），源码零可见中文。

- [x] **R3 · 冲突窗口口径不一致（P3）** ✅
  - 问题：`ScheduleUtils.effectiveEndMin()` 的 NONE 分支取 `scheduledEndMin ?: scheduledStartMin ?: 0`，而 `GetTodayTasksUseCase` 今日视图无结束时间时默认 `start + 30`。两处对同名任务的冲突判定可能相互矛盾。
  - 修复：`effectiveEndMin()` NONE 分支改为与今日视图一致：`scheduledEndMin ?: (start + 30)`，注释同步。

- [x] **R4 · OkHttp Response 未关闭（P3，资源泄漏）** ✅
  - 问题：`OpenAiCompatibleLlmProvider` 的 `client.newCall(request).execute()` 结果未在 `try`-with-resources 中关闭，底层 `ResponseBody` 流可能未及时回收。
  - 修复：整段移入 `execute().use { response -> ... }` lambda，确保响应体关闭。

- [x] **R5 · 备份导入事务原子性（P3，已以 TransactionRunner 抽象重做）** ✅
  - 问题：`BackupManager.importFromJson` 逐仓储直插，中途失败会留下「部分导入」脏数据。理想做法是用 `AppDatabase.withTransaction` 包裹。
  - 重做（2026-07-25）：直接注入 `AppDatabase` 会破坏「mock 仓储纯 JVM 单测」范式（原回退原因）。改为注入 `TransactionRunner` 接口——生产 `RoomTransactionRunner`（`db.withTransaction` 包裹导入写入），测试用 `NoOpTransactionRunner`；两项测试已适配 6 参构造并新增 `TestTransactionRunner` 断言「事务已执行」。零新依赖，保留现有测试范式。
  - 验收：`./gradlew :app:testDebugUnitTest :app:lintRelease` 通过（`BackupManagerTest` 含事务执行断言）。

- [x] **R6 · 备份校验 KDoc 与代码不符（P3，注释误导）** ✅
  - 问题：`validateBackupJson` 上方 KDoc 写「版本缺失/非法或不高于当前 schema 视为 CORRUPT」，但代码为 `if (version > SCHEMA_VERSION) return CORRUPT`（即高于才损坏；≤当前合法版本均通过）。
  - 修复：KDoc 改为「版本缺失/非法（≤0）或高于当前 schema（不支持）视为 CORRUPT」，与代码一致。

- [x] **R7 · SeedUseCase 死代码（P3）** ✅
  - 问题：`SeedUseCase` 中存在 `val today = LocalDate.now().format(...).let { null }`——计算后被 `let { null }` 丢弃，纯死代码。
  - 修复：删除该行，保留其下 `val gMorning = "seed_g_morning"` 等有效逻辑。

- [x] **R8 · MIGRATION_4_5 缺建 taskId 单列索引（P2，迁移自包含性）** ✅
  - 问题：v5 实体 `TaskInstanceEntity` 声明三索引（taskId / dueDateLocal / 唯一三列），但 `MIGRATION_4_5` 仅建后两者、从不建 `index_task_instance_taskId`。正常升级路径因该索引自 v1 遗留保留而侥幸不崩，但迁移**不自包含**——一旦该索引缺失即触发 Room `IllegalStateException: Migration didn't properly handle task_instance`。
  - 修复：在 `MIGRATION_4_5` 补 `CREATE INDEX IF NOT EXISTS index_task_instance_taskId ON task_instance(taskId)`，使迁移幂等且自包含。`AppDatabase` 另暴露 `internal val MIGRATIONS` 供仪器化契约测试引用。
  - 验收：新增 `AppDatabaseMigrationAndTransactionTest.taskInstance_has_expected_indexes` 在真实库断言三索引齐备（CI 模拟器通道）。

- [x] **R9 · 备份导入事务内嵌套读 + 组引用误置空（P1，死锁/ANR + 数据正确性）** ✅
  - 问题：`BackupManager.importFromJson` 在 `txn.run { }`（生产走 `AppDatabase.withTransaction`）内部调用 `groupRepository.observeActive().first()` 读取。SQLCipher 默认连接池常仅 1，事务持有连接时嵌套读另取连接会相互等待 → ANR/死锁，导入卡死。
  - 连带正确性缺陷：有效组集合在事务内读取，且未包含「备份内组」，导致同备份的任务引用了备份内组时被误置 `groupId=null`。
  - 修复：`validGroupIds = 备份内组 ∪ 现有活跃组` 整体移到事务外计算，事务内仅保留写入；彻底消除嵌套读且保证备份内组引用不被误清空。
  - 验收：`./gradlew :app:testDebugUnitTest` 通过（含 `BackupManagerTest` 事务执行断言）。

- [x] **R10 · 小智 WebSocket 传输重连竞态与资源泄漏（P2）** ✅
  - 问题：`WebSocketXiaozhiTransport`
    - `connect()` 在「重连中」（`connected=false`）再次被调用时，会新建作用域并 `openSocket()`，而旧重连延迟回调仍会再建一个 socket → 重复连接、`ws` 被覆盖泄漏、事件重复处理。
    - `disconnect()` 以 `if (!connected) return` 早退：重连中（`connected=false`）离开助手页时不释放 `AudioTrack`/`OpusCodec` → 声音残留、资源滞留。
  - 修复：① `connect()` 重建作用域前 `scope?.cancel()`，`openSocket()` 开头加 `if (ws != null) return` 守卫，消除竞态与重复 socket；② `disconnect()` 移除早退，始终 `runCatching { player.release() }` + `codec.release()` + `scope?.cancel()` + `ws?.close()`（`OpusCodec` 释放后惰性重建，安全）。

> 仪器化契约测试（step 2）：新增 `app/src/androidTest/.../AppDatabaseMigrationAndTransactionTest.kt`，在真实 SQLCipher+Room 库上验证「库可打开/DAO 往返」「R5 事务提交/回滚」「R8 三索引齐备」，由 `ci.yml` 的 `connectedDebugAndroidTest` 在模拟器通道执行。零新依赖（复用已声明 `androidx.room.testing`/`androidx.junit`/`sqlcipher`）。
