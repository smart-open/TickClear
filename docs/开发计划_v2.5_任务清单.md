## 一·补·补二 · v2.5.2 复查修复（2026-07-25，本轮五步工程新发现）

> 来源：用户本轮「五步工程」第二步——独立只读子代理四维/质量扫描 + 人工逐条 Read 源码核实，发现并**当轮修复**以下 7 项（R1–R7）。零新依赖，待 `./gradlew :app:testDebugUnitTest :app:lintRelease` 门禁全绿后提交。
> 其中 **R5（导入事务原子性）因与既有「mock 仓储纯 JVM 单测」范式根本冲突已回退**，列为待 DB 测试基建完备后的后续项（非崩溃，仅极端部分失败场景）。

- [x] **R1 · 全天 / 随时任务永不生成实例（P1，真实功能缺陷）** ✅
  - 问题：`TaskInstanceRepository.ensureInstancesForDate` 仅遍历 `task.dueMinutesForDate(date)`；全天任务（`allDay=true`）与「随时任务」（`scheduledDate=null`）该列表为空 → 不生成任何实例。后果：此类任务从「今日」消失、无提醒、无法完成、不计入统计。
  - 修复：列表为空时插入恰好一个 `dueMinute=null` 的实例（`"${taskId}@$date"`），使其在今日可见、可完成、可纳入统计；`ReminderScheduler` 对 `dueMinute=null` 已安全跳过（不排定点提醒），无崩溃。

- [x] **R2 · 统计页「未分组」硬编码（P2，红线 i18n）** ✅
  - 问题：`StatsUseCases` 柱状图「未分组」分组名以中文字面量写入 `GroupStat`，违反「中文全抽离 `strings.xml`」红线（勋章 i18n 已在 V2.60 收口，此处遗漏）。
  - 修复：新增哨兵 `UNGROUPED_GROUP_ID = "__ungrouped__"`，柱状图改用哨兵 id；`StatsScreen` 据哨兵取 `strings.xml:tasks_no_group`（已有 "未分组"），源码零可见中文。

- [x] **R3 · 冲突窗口口径不一致（P3）** ✅
  - 问题：`ScheduleUtils.effectiveEndMin()` 的 NONE 分支取 `scheduledEndMin ?: scheduledStartMin ?: 0`，而 `GetTodayTasksUseCase` 今日视图无结束时间时默认 `start + 30`。两处对同名任务的冲突判定可能相互矛盾。
  - 修复：`effectiveEndMin()` NONE 分支改为与今日视图一致：`scheduledEndMin ?: (start + 30)`，注释同步。

- [x] **R4 · OkHttp Response 未关闭（P3，资源泄漏）** ✅
  - 问题：`OpenAiCompatibleLlmProvider` 的 `client.newCall(request).execute()` 结果未在 `try`-with-resources 中关闭，底层 `ResponseBody` 流可能未及时回收。
  - 修复：整段移入 `execute().use { response -> ... }` lambda，确保响应体关闭。

- [ ] **R5 · 备份导入事务原子性（P3，已回退·待 DB 基建）** 🔶
  - 问题：`BackupManager.importFromJson` 逐仓储直插，中途失败会留下「部分导入」脏数据。理想做法是用 `AppDatabase.withTransaction` 包裹。
  - 回退原因：注入 `AppDatabase` 后，`BackupManagerTest` / `BackupManagerHealthTest` 因 mock 仓储纯 JVM 单测范式（无真实 `RoomDatabase`）编译失败；与项目既有测试基建根本冲突。
  - 决策（最小代价 + 守红线）：回退 R5，保留 R1–R4/R6/R7 共 6 项测试安全修复；R5 记为「待 DB 测试基建完备后再做」的已知项（极端部分失败场景，非崩溃）。

- [x] **R6 · 备份校验 KDoc 与代码不符（P3，注释误导）** ✅
  - 问题：`validateBackupJson` 上方 KDoc 写「版本缺失/非法或不高于当前 schema 视为 CORRUPT」，但代码为 `if (version > SCHEMA_VERSION) return CORRUPT`（即高于才损坏；≤当前合法版本均通过）。
  - 修复：KDoc 改为「版本缺失/非法（≤0）或高于当前 schema（不支持）视为 CORRUPT」，与代码一致。

- [x] **R7 · SeedUseCase 死代码（P3）** ✅
  - 问题：`SeedUseCase` 中存在 `val today = LocalDate.now().format(...).let { null }`——计算后被 `let { null }` 丢弃，纯死代码。
  - 修复：删除该行，保留其下 `val gMorning = "seed_g_morning"` 等有效逻辑。
