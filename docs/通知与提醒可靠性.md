# 通知与提醒可靠性设计（v2.8X++）

> 本文档说明 TickClear 提醒在「APP 打开 / 后台 / 锁屏」三种状态下的投递模型、可靠性设计与已知限制。
> 对应代码：`domain/scheduler/ReminderScheduler.kt`、`HabitReminderScheduler.kt`、`ReminderReceiver.kt`、`HabitReminderReceiver.kt`、`NotificationHelper.kt`、`BootReceiver.kt`。

## 1. 调度模型（单一事实源 = AlarmManager 系统闹钟）

不依赖 WorkManager，改用 `AlarmManager` 精确闹钟，保证定点送达（PRD §7.2 硬性要求），在 WorkManager 不可用环境同样可靠。

- **两个调度器**：`ReminderScheduler`（任务）、`HabitReminderScheduler`（习惯）。
- **排程入口（统一走，避免孤立闹钟）**：
  - `AddTaskUseCase` / 习惯用例：先 `cancelForTask` 再 `scheduleForTask`（编辑即重排，不产生重复/孤立闹钟）。
  - `BootReceiver`：开机重建渠道 + 重排全部提醒与回收站/位置/自动备份闹钟。
  - `TickClearApplication`：启动兜底重排（已 `runCatching` 保护，绝不阻断启动）。
  - **接收器触发后续排**：任务 `ReminderReceiver` 弹通知后调 `ReminderScheduler.scheduleNext`；习惯 `HabitReminderReceiver` 调 `HabitReminderScheduler.scheduleNext`。这是重复任务「持续提醒」的关键——曾经缺失会导致重复任务首次响铃后永久停摆。
- **未来发生日预排**：`rescheduleAll` 在 60 天窗口内预排「明天/下周」类单次任务，避免重启/进程被杀后若用户次日不打开 App 则闹钟丢失。
- **永不静默丢弃**：目标时刻已过去时，`resolveTrigger` 对一次性任务给 5 分钟宽限（`now+2s`，迟到提醒优于丢失），对重复任务从次日起重排。

## 2. 高优先级 / 习惯走 setAlarmClock（绕开 Doze）

- **`setAlarmClock`**：绕开 Doze 限制、且**免 `SCHEDULE_EXACT_ALARM` 权限**、到点必响，是根治「时好时坏」（锁屏/空闲被系统延迟）的核心手段。
- **中/低优先级**：走 `setExactAndAllowWhileIdle`；无精确权限时 `runCatching` 退化 `setAndAllowWhileIdle`（仍响，可能略有偏移），**绝不抛 `SecurityException` 闪退**（见 `ReminderScheduler.canUseExactAlarms` / `setExact` 安全网）。

## 3. 三态触发路径

| 状态 | 投递机制 | 声/震 | 说明 |
| --- | --- | --- | --- |
| **APP 打开（前台）** | Manifest 广播 `ReminderReceiver`/`HabitReminderReceiver`，系统进程弹出通知 | 按渠道 | 前台不影响系统层闹钟投递；仅全屏意图在 Android 14+ 受「额外提醒权限」约束时降级为普通通知 |
| **APP 后台（未杀）** | `setAlarmClock`（高/习惯）精确投递；中/低 `setExactAndAllowWhileIdle` | 按渠道 | 无精确权限安全退化为非精确，仍响 |
| **锁屏** | `setAlarmClock` 保证到点必响；通知经系统栈展示 | 高优先级 `VISIBILITY_PUBLIC` 显示内容 | 声/震由渠道控制（`setSound`+`enableVibration`） |

> 触发根因：闹钟 = `AlarmManager`（`setAlarmClock`/`setExactAndAllowWhileIdle`）+ Manifest `BroadcastReceiver`（系统级），前台/后台/被杀/锁屏都响，**不依赖 App 进程**。

## 4. 通知渠道（带版本后缀，可重建）

- 五渠道带版本后缀 `v3`（`NotificationHelper.CHANNEL_VERSION`）；`createChannels` 先删旧无版本 ID 再建新版。Android 8+ 渠道不可就地升级，历史静音/无震渠道会永久残留并使新通知静默——靠新 ID 重建修正。
- **高渠道**：`IMPORTANCE_HIGH` + `setSound(notify_chime, USAGE_ALARM)` + `enableVibration(true)` + `setBypassDnd(true)`。
- **高优先级任务 / 习惯始终响铃+震动**，不受全局「声音」开关约束（`ReminderPrefs.shouldForceSound(level) == "high"`）；低优先级命中静音时段降级为 silent 渠道。

## 5. 已知限制（平台/真机约束，非缺陷）

1. **DND 绕过需用户授权**：`setBypassDnd(true)` 生效前提是用户在系统设置授予「通知优先级访问」权限（`ACCESS_NOTIFICATION_POLICY`）。调试页已新增「勿扰绕过」诊断行与跳转设置入口；未授权时勿扰模式仍会静音高优先级提醒。
2. **时区跨区变更**：已排绝对时刻闹钟在跨时区后需下次打开 App / 重启的 `rescheduleAll` 校正（平台固有限制）。
3. **进程强杀极端边界**：若进程恰在接收器续排（`scheduleNext`）执行窗口内被强杀，下一次打开 App / 重启由 `rescheduleAll` 兜底补排。
4. **全屏提醒**：Android 14+ 未获「额外提醒权限」时降级为普通通知（系统隐私策略）。
